# 智萃科研工作台

智萃科研是本机运行的科研工作台：按项目整理材料和论文，围绕具体问题开展检索、筛选、研读与写作，保存提纲、草稿、审查记录及可下载成果。研究任务在首次成文前审校一次提纲，确认后继续成文、内部修订与交付；中途停止后可从已保存进度接续。

工作台使用 TypeScript、Fastify、Next.js / React 和 Pi SDK。模型由用户选择并提供 API 接入；安装和启动应用本身不会调用模型。

## 第一次下载：按这四步使用

这是在自己电脑运行的版本。你需要 **Node.js 22.19 或更新版本**、随 Node.js 安装的 npm，以及自己可用的模型 API。能直接访问文献数据库时无需代理；访问受限时需要这台电脑上已有的可用 HTTP(S) 代理。源码包含代理接入功能，不附带代理服务或订阅。Windows 提供完整的资源管理器和回收站操作；其他系统目前不提供相同的文件管理能力。

### 1. 下载源码并进入目录

在本仓库页面点击 **Code → Download ZIP**，解压后在包含 `package.json` 的文件夹打开终端。已安装 Git 的用户也可执行：

```powershell
git clone https://github.com/Ltto123/zhicui-research.git
cd zhicui-research
node --version
```

版本应为 22.19 或更新版本。如果 GitHub 下载或后面的 `npm ci` 无法连接，先按下方“下载源码和安装依赖时使用代理”设置当前终端。

### 2. 选择文献检索的联网方式

网络能直接访问数据库时可跳过配置。需要代理时，先启动自己的代理软件，再按下方“工作台运行时使用代理”创建 `.env` 并填写实际地址。只打开浏览器代理或系统代理开关，不保证 Node.js 程序会自动使用它。

### 3. 安装并启动

在工作台目录执行：

```powershell
npm ci --fetch-retries=1 --fetch-timeout=30000
npm run dev
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。终端需要保持运行；按 `Ctrl+C` 停止。后端监听 `127.0.0.1:4310`，前端通过同源 `/api` 转发请求。端口固定为 3000 和 4310，若已被占用，先确认是否已有工作台实例在运行。

### 4. 接入模型、检查文献来源，再开始研究

打开左下角 **模型与接入**，填写连接名称，选择接口协议，填写 API 地址、模型 ID 列表和密钥。保存连接后点击 **测试此连接与模型**；这一步会实际调用模型，可能产生费用。然后在同一窗口的 **文献检索与网络** 点击 **检查数据库连接**，分别查看各个来源的结果。模型连接成功和文献来源可连接是两项独立检查；数据库检查不调用语言模型，但会使用数据库自己的请求额度。

关闭设置后，新建项目和对话，在研究输入框旁点击 **选择下次执行模型**，选择刚才连接下实际要使用的模型，再输入研究要求或上传材料。保存连接和测试成功不会自动完成这一步选择。首次写作提纲出来后审校一次，通过后工作台继续写作与交付。完整操作见下方“第一次使用”。

## 代理怎么配置

### 工作台运行时使用代理

以本机代理软件提供 `http://127.0.0.1:7897` 为例。请在软件中确认 **HTTP 端口或 Mixed（混合）端口**；`7897` 只是示例，不是每个人的端口。当前接入支持 HTTP(S) 代理地址，不要填 `socks5://` 地址。`127.0.0.1` 始终指运行工作台的那台电脑。

在包含 `package.json` 的工作台目录中，把 `.env.example` 复制为 `.env`。已有 `.env` 时直接编辑，不覆盖原配置。Windows PowerShell 可执行：

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
notepad .env
```

macOS / Linux 可执行 `[ -f .env ] || cp .env.example .env`，再用文本编辑器打开 `.env`。在文件里设置下面四项；若已有同名字段，修改原行，不重复添加。确保这些行前面没有 `#`：

```dotenv
ZHICUI_NETWORK_MODE=auto
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
NO_PROXY=localhost,127.0.0.1,::1
```

保存后启动工作台。已经运行时，先等正在进行的研究结束或主动停止，再在启动终端按 `Ctrl+C`，重新运行 `npm run dev`；构建版使用 `npm start`。`.env` 在启动时读取，保存文件或刷新网页不会立即切换网络。

进入 **模型与接入 → 文献检索与网络**，应看到“工作台服务器通过代理访问”和所填地址，再点击“检查数据库连接”。这确认的是当前配置和各来源响应，代理端口打开本身不能保证每个数据库或全文地址都能访问。页面目前提供网络状态与检查，代理地址需要在 `.env` 中填写。

要显式使用直连，把 `ZHICUI_NETWORK_MODE` 改成 `direct` 后重启。无需为了直连删除其他模型或数据设置。

### 下载源码和安装依赖时使用代理

`git clone`、`npm ci` 使用启动它们的终端设置，**不会读取工作台的 `.env`**。下载受限时，在执行这些命令的同一个终端先设置下面的环境变量。代理软件必须已启动，地址和端口按实际情况填写。

Windows PowerShell：

```powershell
$env:HTTP_PROXY='http://127.0.0.1:7897'
$env:HTTPS_PROXY=$env:HTTP_PROXY
$env:NO_PROXY='localhost,127.0.0.1,::1'
```

macOS / Linux：

```bash
export HTTP_PROXY=http://127.0.0.1:7897
export HTTPS_PROXY="$HTTP_PROXY"
export NO_PROXY=localhost,127.0.0.1,::1
export http_proxy="$HTTP_PROXY" https_proxy="$HTTPS_PROXY" no_proxy="$NO_PROXY"
```

设置后再执行下载或安装命令。这些设置只作用于当前终端及其启动的程序；需要每次启动工作台都生效的配置写入 `.env`。

### 遇到问题先看这里

| 看到的情况 | 怎么处理 |
| --- | --- |
| 找不到 `node` 或 `npm` | 安装所需 Node.js 版本后，重新打开终端，执行 `node --version`。 |
| `npm ci` 超时、连接失败 | `.env` 不负责安装网络；检查上面的终端代理设置、代理软件是否运行，以及地址端口是否正确。 |
| 工作台仍显示“直接访问网络” | 确认文件名是 `.env` 而非 `.env.txt`，位于 `package.json` 同目录；代理行没有 `#`；模式为 `auto`；保存后已重启。启动日志会说明代理端口不可用后的直连尝试。 |
| 修改 `.env` 后显示的地址仍旧不对 | 已有终端环境变量优先于 `.env`，小写代理变量优先于大写；在该终端修改旧设置，或从没有旧代理变量的终端重新启动。 |
| 模型测试成功，论文来源仍失败 | 两者访问不同网站；点击“检查数据库连接”，按具体来源的错误检查网络、限流或服务状态。 |
| 代理状态正常，部分来源仍不可连接 | 代理端口可达只表示能连接代理软件；继续检查该软件的节点与分流，以及数据库自身是否返回错误。 |
| 检索正常但无法下载某篇全文 | 查看该篇的原文获取记录；全文可能需要机构权限、未公开，或出版方拒绝自动访问。 |

## 使用构建后的版本

依赖安装完成后执行：

```powershell
npm run build
npm start
```

`npm start` 同时启动后端与构建后的前端。当前版本仅监听本机回环地址，没有公网用户认证或租户隔离；不能直接当作多人在线服务部署。

## 第一次使用

1. 打开左下角“模型与接入”，添加连接名称、接口协议、API 地址、模型 ID 列表和密钥，保存并测试。关闭设置后，在研究输入框旁点击“选择下次执行模型”，选择该连接下实际要执行的模型；连接测试不会代替这一步。测试会实际调用模型，可能产生费用。持续研究需要 API 接口；CLI 通道尚不能运行同等科研工具流程。
2. 新建项目和对话，说明本次需要的成果。可上传研究材料、方法要求或格式规范，再明确选择要用于任务的材料。同项目其他对话的材料不会自动全部加入。
3. 研究任务默认在首次成文前展示提纲供审校。可发送修改意见，或确认后继续；确认绑定当时看到的版本，其他窗口更新提纲后需要重新查看。
4. 在成果栏下载 Markdown、HTML 或 Word；本机可用浏览器时另生成 PDF。任务停止或失败时保留已保存工作，可处理原因后继续。

示例请求：

> 基于上传的实验条件和已取得文献，比较现有检测方法，完成一份综述。不要推断未报告的性能参数；先给我审校写作提纲。

> 只复核这份 CSV 中 x、y 的描述统计和线性拟合，交付独立分析报告；没有原始记录支持的结果不要补写。

模型生成和自动审查不能替代科学验证。原文可取得、实际阅读范围、某个主张得到支持分别记录；没有取得的全文、数据或人工核验不能当作已完成。

## 模型、网络与配置

推荐先在界面配置模型。也可将 `.env.example` 复制为本目录的 `.env`，再编辑需要的字段。`npm run dev` 和 `npm start` 会读取这份配置；只加载明确支持的应用字段，已有进程环境变量优先。界面保存的模型连接优先于环境默认值。工作台不会读取父目录或其他项目的 `.env`。

| 配置 | 用途 |
| --- | --- |
| `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY` | 模型 API 默认地址、名称和密钥 |
| `LLM_PROTOCOL` | `openai` 或 `anthropic` |
| `ZHICUI_NETWORK_MODE` | 默认 `auto`；显式代理存在时使用代理，否则限时直连。`direct` 忽略继承的代理设置 |
| `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` | 后端进程使用的代理；同时支持小写字段，小写优先 |
| `ZHICUI_DATA_DIR` | 本地运行数据目录，默认本目录的 `.data/` |
| `ZHICUI_PUBLIC_URL` | 工作台原文链接的 origin，默认 `http://127.0.0.1:3000`；不改变监听地址或访问权限 |

论文检索、DOI 解析和原文获取由运行工作台的后端执行。无需在浏览器中另装检索插件。代理地址中的 `127.0.0.1` 指运行后端的同一台电脑；显式代理不可用时，服务说明原因后尝试有超时的直连。检索接口支持 `NO_PROXY` 的具体域名例外并自动加入本机地址；出版方原文下载的分流实现不同，不能用它保证所有下载均绕过代理。全局 `*` 会被忽略，全部直连请设置 `ZHICUI_NETWORK_MODE=direct`。安装依赖的 `npm ci` 使用终端自己的网络设置，不读取工作台 `.env`。

“模型与接入”可检查 OpenAlex、Crossref、Europe PMC、arXiv、PubMed、ERIC、DOAJ 和 OpenAIRE。连通不等于检索完整或全文可取得；数据库覆盖、机构权限和请求额度仍受来源限制。

PDF 需要可启动的 Chromium 浏览器。Windows 优先尝试本机 Edge / Chrome；未找到时可按需运行 `npx playwright install chromium` 下载 Playwright 浏览器。未生成 PDF 时，界面会说明原因并保留其他已成功生成的格式。默认排版采用宋体和 Times New Roman；实际显示仍取决于阅读或渲染环境的字体。

## 材料与成果

- 支持 TXT、Markdown、CSV、TSV、JSON、DOCX 和带文本层的 PDF。单文件上限 5 MB；单次所选材料文本上限 18 万字符。扫描件 OCR、DOCX 中的 OMML 公式提取尚未实现。
- 论文库保留检索候选、来源与阅读范围；明确收藏到文献夹后可设置个人阅读进度、标签和笔记。个人笔记不会自动进入模型上下文。
- “保存到项目”留下成果副本。Windows 删除操作先显示影响范围，再将相关记录和独有文件打包到回收站；校验成功后才清理原件。归档不清理文件。
- 正式导出保留正文引用和公开参考文献链接，不插入工作台内部运行记录。成功导出不代表已经逐条符合某一投稿规范。
- 已实现顺序编码书目与受支持的页面、字体、行距和常见公式；任意期刊专用模板、所有引用体例和复杂公式转换尚未完整支持。

## 数据与备份

`.data/` 包含项目、对话、上传原件、论文缓存、会话、成果、文献夹及模型连接设置。备份前先停止服务，再复制整个数据目录。升级源码时保留原数据目录，或通过 `ZHICUI_DATA_DIR` 指向独立存储位置。

密钥不会回传到界面，但本地接入设置并不是加密保险库。所选研究材料和相关研究上下文会发送给用户选择的模型服务。不要把 `.data/`、`.env`、运行日志、上传材料或生成稿件提交到公开仓库。

## 源码与内置资源

工作台可以独立运行，不依赖开发者的其他项目或个人 Codex/Claude 配置：

| 路径 | 内容 |
| --- | --- |
| `server/` | API、任务执行、文献处理、持久化和导出 |
| `shared/` | 前后端共用类型与规则 |
| `web/` | 工作台界面 |
| `methods/` | 共同原则与 14 张内置方法卡 |
| `server/upstream/research-skills/` | 运行时所需的三个科研技能：文献综述、引用核对、arXiv |
| `scripts/dev.mjs`、`scripts/startup-config.mjs` | 本机启动与配置加载 |

方法卡、内置科研技能及其来源声明是应用资源，应随源码一起保留。上游来源与改造范围见 [UPSTREAM.md](UPSTREAM.md)，第三方归属和许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) 及相应目录的许可文件。第三方许可不代表本仓库全部原创代码已采用相同许可证。

源码检查可执行：

```powershell
npm run typecheck
npm run build
```

维护者可使用白名单工具准备一个新的源码发行目录：

```powershell
node scripts/prepare-release.mjs --output ./tmp/release-preview --dry-run
node scripts/prepare-release.mjs --output ./tmp/release-source
```

工具只复制运行与构建所需源码、内置方法、科研技能和许可文件，生成逐文件 SHA-256 清单；不会覆盖已有目录。研发测试、验收脚本、个人代理指令、数据、密钥、稿件、缓存和依赖目录不进入发行包。发布前仍需人工复核生成清单和内容。
